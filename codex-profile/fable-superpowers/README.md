# Fable 5 + Superpowers в Gigma Skills

Fable 5 и Superpowers поставляются как плагины единого маркетплейса `gigma-skills`. Общие правила, переносимый установщик и проверяемое обновление находятся в этом профиле маркетплейса. Отдельного навыка для переноса нет.

## Установка на новом компьютере

Нужны Windows, Codex с CLI на PATH, Python 3.11+, Node.js 20+ и Git. Войдите в Codex обычным способом на этом компьютере. Реальные испытания требуют авторизованного доступа к модели и доступной делегации; неподдерживаемая sandbox или версия протокола останавливает проверку.

Клонируйте или обновите Gigma Skills и из корня репозитория выполните:

```powershell
pwsh -NoProfile -File .\codex-profile\setup.ps1 -Workflow FableSuperpowers
```

Предварительный просмотр без создания целевой папки:

```powershell
pwsh -NoProfile -File .\codex-profile\setup.ps1 -Workflow FableSuperpowers -WhatIf
```

`-CodexHome <путь>` задаёт явную папку Codex. Без параметра используется `CODEX_HOME`, затем папка `.codex` текущего пользователя. Установщик выбирает доступный Python, предпочитая встроенный runtime Codex.

Профиль готовит локальную копию полного каталога Gigma Skills в `<CodexHome>/local-plugins/gigma-skills`. Остальные локальные плагины ссылаются на исходный checkout; внешние пакеты сохраняют закреплённые источники. Fable устанавливается как `fable5-codex@gigma-skills`, Superpowers — как `superpowers@gigma-skills`. Уже включённый Fable из другого маркетплейса переиспользуется.

Правила совместной работы добавляются управляемым фрагментом: Fable — общая основа, Superpowers — инженерный workflow, один план и одна проверка каждого этапа. Не связанные с этой схемой правила и настройки сохраняются. Режим не устанавливает прежние generic workflow rules, копии скиллов и feature-хуки Standard-профиля.

Если Gigma Skills уже зарегистрирован из другого каталога, источник сохраняется. После просмотра плана флаг `-AdoptMarketplace` явно разрешает перейти на подготовленную локальную копию всего маркетплейса. Другой активный источник Superpowers, явно отключённый плагин, изменённый управляемый файл или конфликт владельца требуют конкретного решения; они не переключаются молча.

Повторная настройка поддерживает уже управляемый локальный Superpowers. Активная установка из прямого URL-pin сохраняется: её кэш содержит полный Git checkout и не принимается за проверенный неизменяемый пакет. Такая установка отклоняется до записи настроек; для полной схемы используйте чистую домашнюю папку Codex либо отдельно разрешите и выполните переход существующей установки. `-AdoptMarketplace` разрешает только смену источника каталога, а не удаление или переделку кэша плагина.

## Расписание

После успешной установки создаётся `<CodexHome>/local-plugins/gigma-skills/updates/automation-request.json`. В Codex на новом компьютере попросите:

> Прочитай automation-request.json установленного профиля Gigma Skills. Создай или переиспользуй штатное ежедневное обновление Superpowers в этом чате и проверь сохранённое расписание.

Агент должен найти текущий инструмент управления автоматизациями, проверить существующие задания для той же домашней папки и применить только поддерживаемые поля запроса. Служебные поля шаблона не являются аргументами API. Предпочтителен heartbeat текущего чата; новый график — ежедневно в 10:00 по местному времени компьютера. Существующие время и пауза пользователя сохраняются.

Python/PowerShell формирует запрос; сама автоматизация создаётся только штатным инструментом приложения. Старые thread ID и automation ID не переносятся. Если такого инструмента нет, запрос сохраняется с явным статусом ожидания; файлы scheduler TOML, cron и Windows Task Scheduler вместо heartbeat не создаются. Для локального запуска нужны включённый компьютер и работающее приложение Codex.

В prompt сохраняются: дождаться одного запуска, читать свежий результат, не менять правила/разрешения и не обходить проверки. При `unchanged`, `busy`, прежнем удержанном кандидате или повторении уже сообщённого сбоя сообщений не нужно. Уведомления — об установленной версии, новом существенном сбое, восстановлении или необходимом действии.

## Проверки и обновление

Перед первой активацией кандидат проверяется в отдельных тестовых проектах. Только первый bootstrap допускает пустой внешний каталог Superpowers; обычные обновления требуют действующий источник. Проверяются native discovery, настоящее обнаружение и полное чтение через Fable, пять типовых задач, отсутствие лишних планов/вопросов/worktrees, RED/GREEN и реальное независимое ревью.

Пакет готовится из стабильного upstream-релиза по точному commit SHA, с хешами и лицензией. Код и лицензии внешних плагинов остаются в исходных репозиториях; копия только SKILL.md не используется. Дополнительные исполняемые возможности не включаются автоматически.

После успеха меняется только запись Superpowers в локальной копии каталога Gigma. Канонический Git-каталог и его pins не переписываются автоматизацией. Остальные плагины сохраняются. Установка выполняется штатным Codex CLI; проверяется активный кэш и Fable. При несовместимости остаётся текущая версия, при ошибке активации выполняется проверяемый откат. Повторная установка переиспользует собственные действующие доказательства и не запускает идентичные испытания заново.

Установленный `maintenance/Update-Superpowers.ps1` поддерживает:

```powershell
& <launcher-path> -Action check -CodexHome <destination>
& <launcher-path> -Action run -CodexHome <destination>
& <launcher-path> -Action recover -CodexHome <destination>
```

`check` читает доступную версию; `run` проверяет и обновляет; `recover` восстанавливает незавершённую транзакцию обновления. Для восстановления прерванного bootstrap повторите команду установки. Сохраняйте `updates/`, журналы и reviewer receipts, каталоги версий и резервные копии.

Если обычное обновление прервано, профиль останавливается до изменений и повторных испытаний. Сначала выполните указанную им команду `-Action recover`, затем повторите настройку; два владельца восстановления не запускаются одновременно.

Упакованные unit-тесты и результаты предыдущего компьютера не являются доказательством выполнения испытаний на новом компьютере. Итог установки должен содержать реальные версии, результаты проверки, статус сохранности настроек и фактическое состояние расписания.

## Прямая установка плагинов из каталога

Для обычного использования закреплённых версий доступны стандартные команды:

```powershell
codex plugin marketplace add .
codex plugin add fable5-codex@gigma-skills
codex plugin add superpowers@gigma-skills
```

Полная схема общих правил и локального обновления устанавливается режимом профиля выше. Авторизация, полная пользовательская config.toml, история, SQLite, кэши плагинов и машинные пути в репозитории не хранятся.
