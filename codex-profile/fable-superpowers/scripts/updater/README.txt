Superpowers: безопасное обновление локального источника

Запуск: .\Update-Superpowers.ps1 -Action run
Проверка версии без установки: -Action check
Восстановление незавершённой транзакции: -Action recover

Процедура проверяет последний стабильный релиз obra/superpowers через публичный GitHub API. Релиз привязан к точному commit SHA; архив скачивается по этому SHA и проверяется перед подготовкой. Это проверка происхождения и целостности, а не заявление о проверенной отдельной подписи издателя.

Кандидат не включается глобально для тестирования. Он размещается в отдельном неактивном пространстве кэша и включается только в пяти изолированных тестовых проектах. Проверяются навыки и полный текст инструкций через native-каталог и настоящий MCP Fable, RED/GREEN, отсутствие повторных вопросов и этапов, реальное независимое ревью. Источник вне тестов остаётся прежним.

Приёмочные Python-команды после пробных задач выполняются в штатной Windows sandbox Codex с профилем read-only и MXC; команды Git ограничены тестовым workspace. Дополнительные writable roots очищены. Перед исполнением тестового кода проверяется запрет записи в глобальную конфигурацию и сетевого соединения. Если ограничения не подтверждены, проверка завершается ошибкой без запуска тестового кода.

После успешных проверок сохраняются резервная копия и неизменяемый каталог новой версии. Атомарно меняется только путь пакета в локальном marketplace; затем выполняются штатная установка Codex и проверки активного кэша/Fable. AGENTS.md не редактируется. Настройки Fable и прочие пользовательские настройки не восстанавливаются поверх параллельных изменений пользователя.

При ошибке возвращается проверенный старый источник и выполняется проверка отката. Если старый каталог изменён, используется проверенная резервная копия. Незавершённые транзакции восстанавливаются до следующей попытки обновления. Одновременные запуски блокируются. Новые hooks/MCP/apps и другие дополнительные исполняемые возможности требуют ручного решения; они не включаются незаметно.

Временные trust-записи пяти тестовых проектов сохраняются в отдельном журнале до изменения config.toml. После остановки процесса следующий запуск убирает только принадлежащие этому прогону записи. Параллельные изменения пользователя сохраняются; изменённая owned-запись блокирует восстановление и требует проверки.

Состояния: unchanged — новой версии нет; updated — установлена и проверена; held — кандидат не прошёл совместимость; rolled_back — возврат к прежней версии подтверждён; recovery_required/failed — требуется внимание. Повторные проверки модели не запускаются для того же отклонённого кандидата при неизменном контексте проверки.

Диагностика: ../updates/last-result.json и ../updates/runs/.
Транзакция: ../updates/transaction.json.
Резервные копии: ../backups/.
Исходники версий: ../packages/; предыдущий исходный каталог ../superpowers сохраняется.

Автоматический запуск создаётся штатной автоматизацией Codex. Для локальных файлов компьютер должен быть включён, а приложение — запущено. При отсутствии обновлений сообщения не нужны; значимы обновление, новый сбой и необходимое ручное действие.
