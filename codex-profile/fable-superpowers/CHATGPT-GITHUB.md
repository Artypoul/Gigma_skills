# Fable 5 в ChatGPT через GitHub

Режим `chatgpt_github` поддерживается upstream Fable начиная с **1.4.0**.
Он загружает полные инструкции и обязательные зависимости через подключённую
интеграцию GitHub. Установка Codex CLI или локального MCP для самого чтения не
нужна; выполнение кода, независимое ревью и публикация требуют своих реальных
возможностей в текущем чате.

## Источник версий

Сначала агент получает полный SHA текущего реестра `Artypoul/Gigma_skills`, затем
читает на нём оба файла:

- [external-plugins.lock.json](../../external-plugins.lock.json);
- [.agents/plugins/marketplace.json](../../.agents/plugins/marketplace.json).

Версии и источники `fable5-codex` и `superpowers` должны совпадать. Далее агент
читает полный `SKILL.md`, манифесты и необходимые ссылки из исходных репозиториев
по закреплённым SHA. Текст из поиска не заменяет полное чтение.

**Канон правил — upstream Fable:**
`.agents/skills/fable5-codex/references/chatgpt-github.md` на SHA записи Fable.
Этот документ помогает найти маршрут, но не создаёт второй локальный скил или
собственные условия готовности. Пакеты и их лицензии остаются в upstream.

## Запуск в обычном чате

> Примени Fable 5 через подключённый GitHub и выполни задачу: …

Агент сообщает режим, прочитанные версии, полные SHA и ограничения. Статус
`FABLE_MODE=chatgpt_github FABLE_GATE=ready` относится к проверенным инструкциям
и возможностям для запрошенного объёма. Он не означает установку плагина,
прохождение native MCP, завершение тестов, ревью или публикации.

## Инструкции проекта ChatGPT

Возьмите полный шаблон `docs/chatgpt-project-instructions.md` из закреплённой
версии Fable. Короткое правило для проекта:

```text
Перед выполнением задач применяй Fable 5 через подключённую интеграцию GitHub в режиме chatgpt_github. Разреши Artypoul/Gigma_skills в полный SHA, сверь external-plugins.lock.json и .agents/plugins/marketplace.json. Полностью прочитай закреплённый SKILL.md Fable, references/chatgpt-github.md, применимые ссылки и процесс Superpowers с обязательными зависимостями. Следуй каноническим условиям готовности upstream. Сообщи версии и ограничения, сохраняй границы задачи, выполняй реальные проверки и обязательное независимое ревью. Не выдавай чтение через GitHub за native MCP-активацию или завершение задачи.
```

Сохраните правило в **••• → Project settings** нужного проекта и откройте новый
чат внутри него. Задайте обычную задачу без упоминания Fable, например:
«Подготовь только план проверки README; файлы не меняй». Проверьте, что чтение
закреплённых инструкций произошло до работы и исходники остались неизменными.

Сохранение файла в этом репозитории не меняет настройки ChatGPT. Отдельный агент
с переданным правилом проверяет текст инструкции, но не наследование настройки
новым чатом. Факт сохранения и результат нового чата фиксируются отдельно.
Описание интерфейса: [официальная справка OpenAI](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)
(проверено 2026-11-18).

## Проверки и выпуск

Сценарии и границы доказательств находятся в upstream
`docs/chatgpt-github-acceptance.md` и `docs/chatgpt-github-evidence.md`.
Проверяются план без правок, инженерная задача, недоступный/частичный файл,
смена версии во время работы, отсутствие обязательного инструмента/рецензента
и сохранение строгого native MCP-режима.

Сначала выпускается PR Fable. PR реестра закрепляет его точный проверенный
коммит и зависит от первого PR. При squash/rebase перед слиянием реестра нужно
сверить опубликованный SHA, обновить pin при необходимости и повторить чтение
и проверку согласованности. Само создание PR не означает слияние или установку.

Для реестра выполняются `python -B validate_plugin.py`,
`python -B -m unittest discover -s tests -p 'test_*.py'` и проверки переносимого
профиля. Native `cooperation-AGENTS.md`, установщики и MCP-гейты этим маршрутом
не заменяются. Не добавляйте `chatgpt` в список нативных runtime-каталогов.
