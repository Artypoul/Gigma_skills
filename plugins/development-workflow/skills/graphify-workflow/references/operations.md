# Установка, запросы и обновление Graphify

## Различай CLI и MCP

`graphify install` устанавливает или копирует инструкции Graphify-скилла в выбранную платформу. Эта команда не устанавливает Graphify CLI и не подключает MCP; это отдельные действия с отдельными побочными эффектами. Уже подключённый MCP не требует запускать локальные `graphify query`. Сначала проверь, какой сервер и какие инструменты реально доступны. Для MCP следуй инструкциям соединения и работай с тем графом, который оно обслуживает. Для локального графа используй CLI:

```text
graphify query "как поток запускает сервис?"
graphify path "узел A" "узел B"
graphify explain "узел"
```

Проверь side effects wrapper-команды до запуска: launcher может автоматически устанавливать пакет при mismatch даже для `query`. В read-only задаче при несовпадении версии не запускай repair/install; используй уже подтверждённый установленный Python/CLI напрямую или сообщи точный недостающий компонент. В Graphify 0.9.102 `query`, `path`, `explain` и MCP `query_graph` по умолчанию пишут локальный query log. Если нужен read-only/privacy режим, отключи его только для процесса команды через `GRAPHIFY_QUERY_LOG_DISABLE=1`, не редактируя глобальную среду.

Команды и параметры могут меняться: смотри `graphify --help` и `python -m graphify.serve --help` именно в используемом окружении. MCP stdio по умолчанию принимает путь к `graph.json`; транспорт HTTP, адрес, ключ и режим сессий настраиваются отдельно. Не считай локальный HTTP-сервер подключённым к агенту только потому, что он запущен.

## Свежая установка

Для нового CLI окружения документация Graphify указывает `uv tool install graphifyy`; для MCP extra — `uv tool install "graphifyy[mcp]"`. Это варианты установки, а не разрешение менять глобальную среду: используй их только в разрешённом пользователем окружении. Если в проекте уже задан venv, launcher или pinned requirements, следуй им и не обновляй пакет без запроса. Пути интерпретатора определяй из реальной команды/окружения; не копируй чужой абсолютный путь.

Code-only AST extraction и базовые запросы не требуют LLM-ключа. Для такого режима выбирай `GRAPHIFY_BACKEND=none` или соответствующий AST-only режим, если он поддерживается командой. Не отправляй документы, изображения или медиа через backend, случайно выбранный по уже установленной API-переменной: семантическую обработку выполняй только в запрошенном объёме и с разрешённым провайдером.

## Найди документацию установленной версии

Используй Python-интерпретатор того же окружения, где установлен CLI:

```powershell
python -c "import graphify; from pathlib import Path; print(Path(graphify.__file__).parent)"
```

В выведенной директории проверь `skill-codex.md`, `skills/codex/references/query.md` и другие нужные references. Установленные метаданные `graphifyy` можно читать через `importlib.metadata.distribution("graphifyy").read_text("METADATA")`. Выбирай конкретный reference по операции и нужной версии; не копируй upstream-пайплайн целиком в этот skill.

В Graphify 0.9.102 CLI-запрос сопоставляет запрос с фактическими именами/ID узлов через текстовый поиск, а не понимает русские/английские синонимы, стемминг или смысловой перевод. Перед `query` используй термины, реально присутствующие в node labels/ID; если пользователь спрашивает на другом языке, возьми подходящие имена из графа. Смотри `skills/codex/references/query.md` установленного пакета. В read-only задаче словарь изучай только в памяти, не запускай upstream-шаг записи vocab-файла. Отсутствие совпадений — повод попробовать реальные имена узлов или проверить исходник, но не утверждение, что связи нет и не причина автоматически пересобирать граф. MCP запросы подчиняются собственным инструкциям сервера.

## Построение и обновление

Для стандартного проекта предпочитай нативные Graphify `update`, `watch` и exporters, если они выполняют нужную задачу. Добавляй проектный адаптер лишь когда есть конкретно подтверждённый отсутствующий сценарий; не переноси сюда большой launcher/watcher другого репозитория как default. `graphify update <путь>` предназначен для изменённых файлов; `--force` может уменьшить граф после удаления кода. `graphify watch <путь>` запускает watcher. Hooks и платформенная установка `graphify install` изменяют окружение или Git; включай их только если это входит в уже разрешённую задачу. Некоторые upstream-команды для сохранения результата/отражения и обучения (например, `save-result`/`reflect`) пишут в graph или память; не запускай их в read-only запросе или аудите.

Для свежести сравнивай метаданные графа с текущими источниками по механизму проекта (fingerprint, статус watcher или manifest). При ошибке оставшийся старый граф не становится свежим. После обновления проверь артефакты и снова запроси тот же узел/связь через фактический MCP или CLI-клиент.

## Локальное обновление и удалённый CI — разные состояния

Локальный watcher обновляет только данные на этом компьютере. Commit делает изменения видимыми в истории; push передаёт их на удалённый Git; фактический запуск workflow создаёт CI-результат и artifact. Artifact не обновляет локальный checkout сам по себе. Для PR убедись, что build metadata соответствует точному head SHA, его fingerprint совпадает с checkout, проверка открывает именно его исходники, а загруженный artifact содержит ожидаемые файлы и прошёл валидатор. Проверь реальный статус запуска, прежде чем сообщать, что удалённый CI прошёл. Разрешение на эти действия действует только в рамках уже названной задачи; не проси его повторно для того же разрешённого шага и не подразумевай разрешение на не названные commit/push/PR действия.
