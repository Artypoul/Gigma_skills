# Контракты графа процессов

Читай этот файл, когда проект дополняет AST граф каталогом процессов, шагами, callflow или отдельными страницами процессов.

## Источник и AST-якоря

- Проверяй якорь по фактическому файлу, строке и совпавшему диапазону текста. Для AST-связи нужно подтвердить, что символ действительно владеет этой областью кода: используй парсер/Tree-sitter и имя объявленного scope, а не ближайший узел или одну только строку.
- Если точное владение нельзя доказать, оставь шаг с проверяемым source file/line и пометь его `source-only`. Не добавляй AST-ссылку для такого шага.
- При генерации/экспорте рёбер заполняй поддерживаемые версией native `source_file`/`source_location`; custom `evidence_file`, `evidence_location` и `evidence_pattern` не заменяют их. Проверяй эти дополнительные поля и связь `source-reference` только если сам проект их использует — это проектный контракт, а не обязательная схема Graphify.
- Нативные `community` описывают группы связности, а не бизнес-иерархию и не дерево процессов. Если проект закрепляет для process overlay явные community IDs, сохраняй именно эти назначения; не превращай это в запрет на штатное Graphify-кластеризование проектов без фиксированных групп.

## Семантика рёбер и схемы

Различай извлечённый вызов и кураторский порядок только если конкретный проект задаёт такую семантику. Не повышай confidence, чтобы ребро выглядело убедительнее. Сохраняй параллельные связи, исходные метаданные и hyperedges при round-trip; не пересчитывай зафиксированные process-community назначения.

Когда проект добавляет overlay до нативных экспортов, итоговый анализ и отчёт должны строиться уже по финальному графу. Сверяй числа и membership с `graph.json`, analysis JSON, build metadata и report. Проверяй страницы процессов и ожидаемые переходы по фактически отрисованным Mermaid statements/SVG, а не только по JSON или заголовку. Сверяй schema и поля инструмента с установленной версией; не предполагай, что `get_node` возвращает поле, отсутствующее в его schema/ответе.

Если custom legend проекта закрепляет solid/dashed за вызовом/кураторским порядком, проверяй оба типа и полный набор переходов. Это не универсальное кодирование нативных Graphify confidence. В Graphify 0.9.102 документированная confidence-шкала: `EXTRACTED` = 1.0; `INFERRED` выбирается из 0.95, 0.85, 0.75, 0.65, 0.55; `AMBIGUOUS` — примерно 0.1–0.3. Не меняй confidence ради отрисовки. Нативный Mermaid callflow включает все `EXTRACTED`; из `INFERRED` включает только рёбра со score ≥ 0.85. Более слабые inferred-связи комментируются для review. Проверяй правила своего установленного выпуска; не переноси эту границу на будущие версии или custom renderer.

## Предел доказательств

Граф и ручной каталог объясняют заявленные статические связи; они не доказывают реальный runtime-порядок, точность интерфейса, актуальность внешнего CLI/API или поведение production. Подтверждай значимые утверждения исходниками, тестами или фактическим протоколом; называй неподтверждённое предположением.

## Если нужно собирать граф через Python API

Проверь API в установленном пакете и используй его штатные функции вместо придуманного builder. В Graphify 0.9.102 валидные `file_type` — `code`, `document`, `paper`, `image`, `rationale`, `concept`; доступны `graphify.build.build_from_json` и `graphify.export.to_json`. При экспорте восстановленных связей передавай исходный массив как `original_links`, когда он есть: иначе простая модель графа может потерять параллельные рёбра. Это детали конкретной версии, а не общая схема API будущих выпусков.

## Доказательство перезагрузки MCP

Для read-only проверки сначала получи фактический список tools и их schemas, затем прочитай ответ инструмента без предположений о незапрошенных полях. Если нужно проверить hot reload маркером, делай это только когда такая временная запись разрешена текущей задачей: сохрани исходные bytes/hash, выбери существующий узел и поле, которое реально возвращает нужный tool, отправь маркер и вызови тот же tool в той же MCP-сессии. Дождись статуса свежей сборки и проверь уже открытый URL браузера, если важно. Затем восстанови исходные bytes и сверь hash. Отсутствие `description`, другое поле schema или задержка ответа не являются основанием для рестарта.
